# SJTU Sports Venue Monitor (Terminal UI)

A small Python script that polls SJTU Sports venue availability and shows a continuously auto-refreshing terminal dashboard.

For a browser panel with clickable venue and date choices that uses the signed-in page's cookies automatically, see the [userscript guide](USERSCRIPT.zh-CN.md).

## Features

- Auto-refreshing terminal UI (no scrolling logs)
- Monitors multiple venues/dates in a loop
- Caches daily `dateId` mappings per venue and field type; refreshes dates after midnight
- Shows pending, available, unavailable, and failed checks with field, time, count, and check time
- Attention-catching alert when a new available slot appears:
  - terminal bell (`\a`)
  - highlighted banner inside the UI

## Requirements

- Linux/macOS/Windows with Python **3.10+** (recommended: 3.11/3.12)
- Python dependency: `requests`

Install dependency:

```bash
pip install requests
```

## Setup

1. Configure `TARGET_CONFIGS` in `config.py`. Adjust `HEADERS` there if needed.

2. After signing in, copy the complete Cookie value from a successful venue request's Request Headers into the local `cookies.json` file:

```json
{
  "cookie_header": "cookie_name=actual_value; another_cookie=actual_value"
}
```

You do not need to identify a specific session cookie. `cookies.json` takes precedence over the older environment settings and is Git ignored. Keep it private.

3. (Optional) Adjust `POLL_INTERVAL` (idle time after a full scan) and `CHECK_INTERVAL` (pause between requests) in `monitor.py`. The total time between scans also includes request time.

## Usage

Run the monitor:

```bash
python main.py
```

### Filter by venue type

If your `TARGET_CONFIGS` items include a `type` field (case-insensitive) such as `tennis`, `badminton`, `gym`, you can filter what gets monitored:

```bash
python main.py --tennis
python main.py --badminton
python main.py --gym
```

You can also combine them:

```bash
python main.py --tennis --gym
```

If you specify a filter but nothing matches, the program will exit with `No tasks to monitor. Exiting.`

## Reading the UI

The dashboard shows:

- current time, cycle number, and total checks
- which task is currently being checked
- **AVAILABLE SLOTS**: confirmed field, date, time, count, and check time for this scan
- **CHECK STATUS**: pending, available, unavailable, and failed counts and task details
- **PREPARATION FAILED / RECENT ERRORS**: date setup failures and historical errors

When spare venues are found, you should see:

- a terminal bell for newly available slots (if your terminal supports it), without repeating it for unchanged availability each cycle
- a highlighted banner near the top of the UI

## Files

- `main.py`: CLI entrypoint and target selection
- `monitor.py`: polling logic + terminal UI
- `config.py`: targets, headers, and local cookie loading
- `cookies.json`: local Cookie configuration (do not share or commit)
- `date_id_cache.json`: local daily cache generated by the program; no longer tracked by Git
- `fresh_date_ids.py`: force-refresh all configured date IDs (`python fresh_date_ids.py`)
- `sjtu-venue-monitor.user.js`: browser userscript; see [installation guide](USERSCRIPT.zh-CN.md)
- `tests/test_monitor.py`: offline regression tests (`python -m unittest discover -s tests`)

## Notes / Troubleshooting

- **No bell sound?**
  - Some terminals disable the audible bell; you may need to enable it in terminal settings.
- **Requests failing / empty results?**
  - Check your login cookie environment variable, then inspect failed checks and error details in the UI.
  - For `API error 401`, sign in again and inspect the complete Cookie value of the actual `sports.sjtu.edu.cn` venue request in your browser's Network panel. The two `_ga` cookies supplied earlier were rejected by the API. Update `cookies.json` and restart.
- **Too noisy / too slow?**
  - Tune `POLL_INTERVAL` and/or reduce `TARGET_CONFIGS`.
